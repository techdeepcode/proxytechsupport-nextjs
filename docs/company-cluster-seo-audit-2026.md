# Company Cluster — SEO Architecture Audit (September 2026)

Additive **500-Company Tech Employer Cluster + Centralized Company Support Dashboard**.
This document records the existing architecture the new cluster plugs into. No production
behaviour is changed by the audit itself.

## Framework & build

- **Next.js 16.2.3**, App Router, `output: 'export'` (fully static). Build runs
  `node scripts/verify-content-urls.mjs && next build`.
- Windows dev host; PowerShell + Bash available.
- ~1,799 route directories under `app/` today (established, ranking production site).

## How pages are generated (the pattern we mirror)

1. **Data factory** in `data/<cluster>/` produces a `LandingPageConfig[]`
   (interface in `data/landing-pages.ts`). Compact "thin builders" fill boilerplate
   (`canonical`, `lastmod`, geo/timezone/CTA defaults) so each page only declares unique copy.
2. Each cluster's aggregate is spread into `allLandingPages` in `data/landing-pages.ts`.
3. `app/sitemap.ts` maps `allLandingPages` → sitemap URLs **automatically** — adding a page
   to the aggregate puts it in the sitemap with a self-referencing canonical.
4. A **generator script** `scripts/gen-<cluster>-cluster-pages.mjs` transpiles the data index
   to CommonJS with the local `tsc`, reads every `slug`, and writes one physical
   `app/<slug>/page.tsx` per slug. **Idempotent** — never overwrites an existing route
   (respects the add-only rule).
5. Each generated `page.tsx` imports the config by slug and renders `LandingPageTemplate`,
   with `metadata = landingPageMetadata(config)` (`lib/site-seo.ts`) — unique title,
   description, canonical, hreflang alternates, OG + Twitter, `robots: index,follow`.

Existing clusters using this exact pattern: `amazon`, `aws`, `azure`, `aiml`, `angular`,
`huggingface`, `workday`, `uipath`, `dotnet-cluster-pages`.

## Directory / dashboard pattern

`/knowledge-base/` = server page wrapper (`app/knowledge-base/page.tsx`) with
`CollectionPage` + `ItemList` JSON-LD, hosting a **client** component
`components/KnowledgeBaseExplorer.tsx` that does search + category chips + card grid over a
data array (`data/knowledgeBaseGuides.ts`). Company dashboard mirrors this exactly.

## SEO infrastructure

- `lib/site-seo.ts` → `landingPageMetadata()`, `defaultOgImage`, `SITE_URL`, `SITE_NAME`.
- `app/sitemap.ts` (`force-static`) — static routes + `allLandingPages` + posts + interviews +
  curated cluster route blocks + research. New landing pages flow in automatically.
- `app/robots.ts` — audited; not blocking content; exposes sitemap.
- `public/llms.txt` + `public/llms-full.txt` — curated, generated by `gen-*-llms.mjs`.

## Risks & mitigations

- **Thin/doorway risk** → dedicated hub pages only for Tier A (genuine, verified,
  company-specific content). Tier B–D are represented as searchable dashboard cards that
  already answer "do you support X?" and link to the most relevant existing service page —
  no blind permutations, no token-swapped pages.
- **Orphans** → every hub is linked from `/tech-companies/`; dashboard linked from homepage,
  navbar and footer.
- **Amazon** → `locked: true`, excluded from generation, card points to existing cluster.
