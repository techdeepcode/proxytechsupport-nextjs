# Proxy Search Cluster 2026 — Knowledge-Base & Blog Content Plan

_Last reviewed: September 2026._

This is the internal planning document for the proxy interview / proxy job support
knowledge-base and blog expansion. It is **additive**. No existing route is renamed,
removed, or re-canonicalised. Before any new URL was proposed, the repository was
searched for an existing page that already targets the same intent; where one exists,
the plan is to **enhance and link**, not duplicate.

## 1. Existing-site audit (what already exists)

The production site is large (~1,700 App Router segments plus content collections).

## 2. Gap analysis → what this phase adds

troubleshooting decision trees, architecture explainers, comparison guides and
interview-knowledge pieces from Phase 26 of the brief that can earn organic and
AI-citation traffic independently of the commercial service, then route readers to
the relevant proxy interview / job-support pillar with a single contextual CTA.

These are evergreen references, so they live in the blog-articles system alongside
the existing deep technical articles (consistent with the Bedrock/SageMaker set) at
`/blog/<slug>/`. They are **not** timely/editorial posts and carry no market
statistics.

## 4. Cannibalisation decisions — URLs intentionally NOT created

- **No `*-proxy-interview` + `*-proxy-interview-support` split.** e.g. "aws proxy
  interview" and "aws proxy interview support" share one canonical. "cyber security"
  and "cybersecurity" are never split.
- **No per-keyword pages.** Synonyms collapse to the canonical pillar above.
- **No new city × technology × service doorway pages** (Phase 8). Country/tech pages
  satisfy those queries.
- **No duplicate RAG explainer.** `/blog/rag-aimlops-retrieval-augmented-generation-guide/`
  stays the "what is RAG" canonical; the new RAG pieces (#5–#7) target distinct
  troubleshooting/comparison intents and link to it, not compete with it.
- **No duplicate Bedrock RAG troubleshooting.** #5 is vendor-neutral (retrieval
  quality across any stack) and links to the existing Bedrock-specific guide.

## 6. Structured data, sitemap, llms

- **Schema:** every article emits `TechArticle`/`BlogPosting` + (where genuinely
  useful) `FAQPage` via `ArticleStructuredData`. FAQ sections are reader aids, not the
  ranking strategy (Google dropped FAQ rich results in 2026).
- **Sitemap:** no change required — `app/sitemap.ts` maps over `getAllPosts()`, so
  every new blog article is included automatically with its canonical `/blog/<slug>/`.
- **llms.txt:** a new "Knowledge Base — Engineering Guides" section lists the 10
  canonical articles. `llms-full.txt` left to its existing generators; no keyword dump.
- **IndexNow:** existing `scripts/submit-indexnow.mjs` can be run post-deploy for the
  new canonical URLs. Not fired here (Phase 31 — do not deploy yet).

## 7. Quality gate

Each article: answers a distinct question, adds substance not already on the site,
is bookmarkable/citable, has a meaningful parent + internal links, is different from
existing URLs, and would be worth publishing even if search did not exist. Articles
that failed this gate (thin city/keyword variants) were not created.
